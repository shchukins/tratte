# Security and public repository checklist

Этот репозиторий рассчитан на открытый исходный код, но рабочая конфигурация и
данные всегда должны оставаться на домашнем сервере.

## Никогда не коммитить

- `.env` и любые файлы с реальными переменными окружения;
- `client_secret*.json`, OAuth access/refresh tokens и `TOKEN_ENCRYPTION_KEY`;
- Telegram bot token и реальные Telegram user ID;
- дампы PostgreSQL, SQLite-файлы, резервные копии и логи;
- экспортированные `.eml`/HTML-письма, Gmail message ID, адрес покупателя/магазина,
  ИНН, ФН, ФД, ФПД и реальные email-адреса пользователя;
- приватные ключи, сертификаты и SSH-конфигурацию.

Эти категории покрыты `.gitignore` и `.dockerignore`, но ignore-файл не защищает
данные, которые уже были добавлены в Git. Перед каждым публичным push проверяйте:

```bash
git status --short
git diff --cached --name-only
git diff --cached
git ls-files | rg '(\.env$|client_secret|credentials.*\.json|\.eml$|\.dump$|\.backup$)'
```

Последняя команда не должна находить чувствительные файлы. Публичные адреса ОФД в
конфигурации и документации являются ожидаемым исключением.

## Домашний сервер

- Храните `.env` и `client_secret.json` с правами `0600`.
- Не публикуйте порт PostgreSQL. В Compose у БД намеренно нет секции `ports`.
- API привязан к `127.0.0.1`; для удалённого доступа используйте VPN или reverse
  proxy с TLS и аутентификацией, а не прямой проброс в интернет.
- Храните `TOKEN_ENCRYPTION_KEY` отдельно от резервных копий БД. Без ключа OAuth
  token в БД зашифрован; вместе с ключом дамп даёт доступ к Gmail в пределах
  read-only scope.
- Шифруйте резервные копии и регулярно проверяйте восстановление на отдельной БД.
- Обновляйте базовые Docker-образы и зависимости после тестирования.

## Если секрет попал в GitHub

Удаление файла новым коммитом недостаточно: значение остаётся в истории.

1. Немедленно отзовите/замените секрет у Google, Telegram или в `.env`.
2. Остановите затронутые контейнеры до замены конфигурации.
3. Очистите историю репозитория подходящим инструментом и принудительно обновите
   удалённые ссылки только после уведомления всех, у кого есть клоны.
4. Проверьте журналы доступа и заново авторизуйте Gmail при утечке OAuth-данных.
