# Этап 1: оценка локальной модели для товаров

Связанная задача: https://github.com/shchukins/tratte/issues/1.

Этот стенд не подключается к БД и не изменяет нормализацию, импорт или отчёты
Tratte. Он отправляет названия через OpenAI-совместимый API и записывает результаты
в отдельный локальный каталог. Интеграции этапов 2–3 здесь нет.

## Статус исследования

Этап 1 закрыт 07.10.2026. Qwen3-4B сохранена как baseline, без автоматической
категоризации, массового объединения и автономных решений. Возможны только
предложения с подтверждением; их интеграция не выполнена.

Дальнейшее направление будет уточнено позднее для сравнения с более сильной
облачной LLM через API. Benchmark, точный prompt и scoring фиксируются в
[frozen_protocol.json](frozen_protocol.json). Их нельзя незаметно менять при
сравнении моделей. Краткий итог и ограничения — в [REPORT.md](REPORT.md).

## Выборка и эталоны

`cases.json`: 100 синтетических уникальных названий (по 10 на каждую из девяти
категорий и «неизвестно»), 35 пар (10 совпадений, 16 различий, 9 случаев нехватки
данных). Названия брендов в парах вымышленные. Метки составлены агентом вручную;
пользователь ещё не проверил эталон. Набор содержит специально сложные случаи
для текущих правил и не представляет частоты покупок пользователя.

Категории соответствуют существующим CATEGORY_RULES плюс «другое» и
«неизвестно». Политика для спорных групп явно закреплена в CATEGORY_PROMPT.
«Другое» — понятный товар вне категорий, «неизвестно» — неясный тип товара.
Для пар нужен один товар и одна упаковка, а не просто похожая товарная группа.
Смена бренда, вкуса, жирности или размера упаковки — различие; отсутствие
существенного признака — insufficient. Массу нельзя приравнивать к объёму.

Проверка пилота начинается с разных классов по очереди, поэтому --limit 10
для категорий включает все классы, а --limit 3 для пар — все типы отношений.
Это отбор по эталонным классам для покрытия, не случайная производственная выборка.

На синтетическом наборе текущие правила без алиасов дают 46/100 верных решений.
Это baseline только этого набора, не оценка качества на рабочих данных.

## Запуск

Сначала проверить фактический runtime, модель, квантование, доступность API,
chat template, поддержку response_format и enable_thinking. Не запускать
полную выборку до успешного пилота. Проверенный endpoint эксперимента: http://127.0.0.1:18081/v1 через SSH-туннель;
model ID: tratte-qwen3-4b-q4km.
API-ключ при необходимости передаётся через PRODUCT_EVAL_API_KEY и не записывается
в manifest. URL должен указывать на доверенный локальный сервер или SSH-туннель.

Команда использует установленный Python виртуального окружения:

```bash
.venv/bin/python -m experiments.product_normalization.evaluate \
  --base-url http://127.0.0.1:18081/v1 \
  --model tratte-qwen3-4b-q4km \
  --limit 10 --repeats 2 \
  --output .local-evaluations/pilot-v1
```

Если schema-constrained вывод не поддерживается, явно использовать --no-schema
с новым каталогом. JSON всё равно строго проверяется в Python; лишние поля,
неразрешённые значения, прерванные ответы и примесь thinking-текста считаются
ошибкой, а не извлекаются эвристически. Это проверяет пригодность фактической
конфигурации, не только способность модели угадать метку.

Полный запуск после пилота:

```bash
.venv/bin/python -m experiments.product_normalization.evaluate \
  --base-url http://127.0.0.1:18081/v1 \
  --model tratte-qwen3-4b-q4km \
  --output .local-evaluations/full-v1
```

Для сравнения режима рассуждений повторить тот же пилот с --thinking в новом
каталоге. Бюджет ответа: 96 токенов без reasoning, 1024 с reasoning. Усечение
ответа считается ошибкой; эти бюджеты зафиксированы в manifest. Сравнение
отражает пригодность режимов при таких бюджетах, не максимально достижимое качество.
Если runtime игнорирует enable_thinking, режим нельзя считать проверенным.

--resume продолжает только идентичную конфигурацию и выборку. Сохранённые
запросы, включая неудачные, не переотправляются. Для повторной проверки ошибок
нужен новый каталог. Три последовательные ошибки останавливают прогон, чтобы
не продолжать запросы к неработающему серверу. Тайм-аут по умолчанию — 60 секунд
на запрос, его можно изменить через --timeout.

Результаты: manifest.json, responses.jsonl и summary.json. Manifest содержит
хеши набора, промптов и правил, ID модели и параметры. Отдельно фиксировать
версию runtime, квантование, модельный файл/хеш и состояние аппаратного ускорения:
model ID API сам по себе их не подтверждает. Температура 0 и seed 42 не гарантируют
повторяемость между сборками или аппаратными конфигурациями.

## Метрики и ограничения

- Доля валидных ответов и accuracy с ошибками в знаменателе.
- Для категорий: baseline правил, accuracy известных категорий, accuracy среди
  классифицированных ответов, число отказов.
- Для пар: ложные объединения (включая insufficient, ошибочно принятые за same),
  пропущенные совпадения, precision и recall объединений, число отказов.
- Медиана и максимальная задержка каждого запроса; это наблюдаемое HTTP-время,
  которое включает очередь, но не является полноценным нагрузочным тестом.
- Согласованность повторов; повторённые невалидные ответы не считаются стабильными.

Повторы не являются независимыми примерами: число уникальных случаев указано
отдельно. Самооценка confidence не запрашивается и не используется. По небольшому
синтетическому набору нельзя разрешать автоматическое массовое объединение.

Для выводов по Tratte нужна отдельная проверенная выборка реальных названий,
которую держим в .local-evaluations и не коммитим. Текущие category в БД — результат
старых правил, а не эталон. Список unlabelled кандидатов не пригоден для runner,
пока expected не заполнен и набор не приведён к контракту cases.json.

## Подтверждённый runtime

- Домашний сервер: human-engine-home, Intel Core i7-6700T, CPU only.
- llama.cpp: 0.5.0-dev build 1, commit a55e952b85741249fcbf120bcd9d47cf2b1f6e48.
- Модель: Qwen/Qwen3-4B-GGUF:Q4_K_M, 4 022 468 096 параметров.
- SHA256 GGUF: 7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5.
- Генерация и обработка промпта: по 6 потоков; context 4096; один слот.
- Модель загружается offline из существующего HF-кэша, без скачивания.
- API слушает только loopback на порту 18081. Для эксперимента используется SSH-туннель.
- Ответы с JSON-схемой работают. enable_thinking меняет режим; reasoning приходит
  отдельно в message.reasoning_content.

Команда временного сервера (на домашнем хосте):

```bash
/home/shch/llama.cpp/build/bin/llama-server \
  --offline -hf Qwen/Qwen3-4B-GGUF:Q4_K_M \
  --threads 6 --threads-batch 6 --device none --gpu-layers 0 \
  --ctx-size 4096 --parallel 1 --host 127.0.0.1 --port 18081 \
  --alias tratte-qwen3-4b-q4km --reasoning auto
```

На локальном компьютере:

```bash
ssh -N -L 18081:127.0.0.1:18081 human-engine-home
```

Runtime metadata сохраняется отдельно в .local-evaluations/runtime-cpu-v1.json.

## Рабочие данные

Read-only проверка 06.10.2026: 413 товарных строк, 186 уникальных original_name,
182 normalized_name; 250 строк имеют категорию «другое». Их нельзя автоматически
считать ошибками. Только названия, частоты и существующие категории сохранены
локально в .local-evaluations/production-candidates-unlabelled.json.
Письма, фискальные реквизиты и токены не выгружались.

Для предварительной оценки вручную размечены агентом 100 наиболее частых
original_name в .local-evaluations/production-reference-v1.json, до получения
ответов модели. Это частотная выборка уникальных названий, не случайная выборка
всех покупок. Пользователь не проверил эталон; спорные сокращения могут менять
оценку. Частные названия и ответы модели не включаются в Git. В отчёт допустимы
только агрегаты, хеши и ID ошибок без названий.
