# Issue #4: реализация SQL-слоя

Дата: 26.10.2026. Контракт: `expense_marts_v1`.
Спецификация и воспроизведение: [MARTS.md](../MARTS.md).

Добавлены четыре обычных PostgreSQL views (чеки, позиции, сверка и агрегаты
качества), миграция `0004_analytical_marts`, параметризованный SQL подтверждённой
части и приватный CLI `analytics marts`. Mapping выбирается явно и проверяется
в той же REPEATABLE READ READ ONLY транзакции. Материализация, scheduler,
декомпозиция #5, настройки дашборда #6 и применение реального review не входят
в эту реализацию.

Все поля/grains/знаменатели и ограничения доступа описаны в MARTS.md. BI role
получает SELECT только четырёх безопасных views; настройка конкретного подключения
Superset выполняется администратором отдельно по `sql/grants_v1.sql`.
Подтверждённый результат нельзя получать обходным SQL JOIN без validate_version.

Локально: **171 passed**, без skipped, включая PostgreSQL с одноразовой БД и
временными схемами/ролью. Проверены grains, полночь Москвы, пустые периоды,
валюты/возвраты/null/0, скидочная арифметика, цена total/quantity, kg/l/piece,
порог различных чеков и store-фильтр, stale gate, конкурентная запись,
отсутствие приватных полей, права BI, повторная установка и откат/повтор миграции.
Ruff и git diff --check прошли. Wheel собран; все три SQL-файла включены в него.
Команда доступна через `python -m app.cli analytics marts --help`.

Production read-only проверка обнаружила отдельный инфраструктурный блокер:
таймер deploy активен, но fetch с GitHub по SSH/22 завершается connection timeout.
Проверенный на момент чтения серверный HEAD/.deploy-revision — `e533886`, то есть
до каталога #3 и витрин #4. Настройки SSH, production schema, review и Superset
