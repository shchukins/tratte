Версия **6.1.0**, получена через package metadata контейнера, не по Docker latest tag.
Найдены virtual datasets в database_id=4:

| --- | --- | --- |
| 24 | tratte_receipts | Чек, общие суммы и временные разрезы |

Сохранено 15 charts на этих datasets. **В действующем layout дашборда #12 только
пять**: 123 (Today), 124 (Week), 125 (Current month), 126 (heatmap), 127 (line).
Наличие других charts в метаданных не означает их отображение на текущей странице.
В существующих charts используются big_number_total, echarts_timeseries_bar/line,
pie и heatmap_v2. **Waterfall Chart найден в UI-каталоге All charts**; установка
нового plugin для MVP не нужна. Его рендер и свойства проверяются на витрине #6.

Native filter «Период»: default `Last month`; scope исключает 123/124/125/127.
У текущего layout фактически отфильтровывается только heatmap 126.
В авторизованном браузере проверено:

1. `Last month` раскрывается как **25.09 ≤ col < 25.10** — это скользящий месяц.
2. `Previous → previous calendar month` показывает **01.09 ≤ col < 01.10**.
3. После Apply график 126 завершил обновление, Applied filters показывает
   `Период: previous calendar month`.
4. В его Explore реально отображается temporal filter
   `2026-09-01 ≤ purchased_at < 2026-10-01`.
5. Исключённые карточки Week/Current month не изменились; на графике 127 показана
   вся история, а не отфильтрованный сентябрь. Dashboard/Chart Save не нажимались.

`cross_filters_enabled=true` в metadata проверен; это не доказывает, что любой тип
графика умеет отправлять фильтр. В активном layout нет товарного графика или
drill до item_id. Переход «фактор → товар → чек» предстоит построить и проверить #6.
Поддержку кросс-фильтра для выбранной новой визуализации нельзя вывести из флага.

Два ограничения семантики существующего BI:

- Все три SQL используют `ILIKE '%ВОЗВРАТ%' → -ABS(total)`, иначе оставляют сумму.
  Unknown проходит в итог как обычная сумма; это не контракт подтверждённых
  purchase для факторного анализа. Нужны новые versioned datasets, не молчаливая
  замена определения существующих отчётов.
- Chart 127 назван «Средний чек за день», но dataset считает средний **расход за
  календарный день** (daily_spend, включая дни без покупок), а не средний чек.
  Для нового кейса обязательно согласовать подпись и знаменатель.

## Решение и следующий шаг

Подробный [ADR-001](../ADR-001-analytical-identity.md): отдельный минимальный
аналитический каталог конкретных вариантов + версии + подтверждаемый item mapping.
Сначала вручную проверить восемь кандидатных ключей и упаковки, без массового
backfill. Исходные поля ReceiptItem/ProductAlias и импорт сохраняют текущую роль.

Текущий результат: descriptive_only для записанных сумм; **insufficient_data для
price/quantity**, поскольку подтверждённых соответствий нет. Следующий шаг — #3,
после него SQL-витрины #4 и расчёты #5. Основной UI можно оставить в Superset.
